# 一、这一层到底负责什么

管理员层与影子档案层的职责，不能理解成“下一关”或“更深网站”。  
它们在《镇锁》里的任务，是完成以下五件事：

## 1.1 把“有人在删东西”翻成“有人在按流程删东西”
论坛层已经告诉玩家：
- 有内容被处理  
- 有词会触发折叠  
- 有账号状态异常

但这还停留在“结果感”。  
管理员层必须进一步让玩家感到：
**删帖、封号、转移、清理，是一整套可被执行、可被记录、可留下痕迹的管理流程。**

## 1.2 把 `8023` 从被吐槽的怪维护，翻成真正的内部视角
论坛层对 8023 的处理是：
- 他像一个真实存在的人  
- 社区里有人见过他  
- 他的口头特征和夜班痕迹都成立

管理员层要再走一步：
**让玩家开始意识到，8023 不只是一个被提起的人，而是某个真正碰过后台、碰过处理流、碰过影子档案边界的人。**

## 1.3 让“影子档案”成立
影子档案不是突然出现的神秘仓库。  
它必须像一件合理的事：
- 有人知道系统会删内容  
- 有人知道前台信息不可信  
- 有人开始偷偷留证据  
- 这些差异节选不完全、不整洁、带着工程师气味

## 1.4 把赵启从“论坛里反复被提到的人”推进成“留下结构的人”
到了这一层，赵启不能还只是人物轮廓。  
玩家必须开始感到：
- 这些东西不是自然残留  
- 有人故意整理过  
- 有人知道什么该留、什么要拆开留、什么不能一次给完

## 1.5 把玩家送往 OA，而不是把 OA 硬塞出来
这一层结束时，玩家不应觉得：
“系统突然给我开了新地图。”

而应觉得：
**“我顺着处理链、管理员边界和影子档案痕迹，终于摸到了真正更深的内部层。”**

# 二、这一层的体验定位

## 2.1 体验定位一句话
这一层是《镇锁》的**第一次制度化下潜**。

论坛层更多还是“民间视角 + 被压制声音”。  
管理员层与影子档案层开始把“异常”翻译成：
- 审核逻辑  
- 处理节点  
- 后台痕迹  
- 证据结构  
- 清理与留存的斗争

## 2.2 这一层的核心问题
这一层只能围绕一个问题组织：

**谁在系统内部留了路，而这条路是怎么留下来的？**

不是“B2 到底是什么”，那是下一层。  
不是“Meridian 到底有多大”，那也不是这一层。  
这一层聚焦于：
- 处理链  
- 证据链  
- 赵启留下的结构

## 2.3 这一层的玩家感受目标
玩家应逐渐从：
- 追帖子
过渡到：
- 追处理痕迹
再过渡到：
- 追证据结构

也就是说，玩家的视角开始从“用户”变成“半个维护者 / 调查员”。

# 三、总语法与交互规则

这一层依然服从**统一搜索框**。  
不新增第二套“管理员系统搜索”或“影子档案搜索”语法。

## 3.1 允许的动作
- 搜索管理员对象  
- 打开边界页  
- 阅读处理记录  
- 阅读影子档案目录  
- 打开 README / 归档说明  
- 顺着记录号与相关记录继续下潜

## 3.2 不允许的动作
- 靠猜 URL 直接进入深层  
- 靠输入随机密码硬闯  
- 靠 hover 找隐藏入口  
- 靠源码再次承担唯一主推进

## 3.3 这一层的记录密度原则
这一层的信息密度要明显高于论坛公开层，但仍不能一口气解释整个世界。  
单条记录默认仍遵守：
- 1 个主关键词  
- 1 个支撑关键词  
- 0–1 个余波关键词

但允许：
- 记录之间形成更强的目录关系  
- README / 目录页承担更高的信息压缩度  
- 处理日志页出现更明确的时间与状态字段

# 四、这一层的记录类型

这一层只使用以下八类记录：

## 4.1 AD-EDGE｜管理员边界记录
作用：显示论坛管理层真实存在，但仍未完全越界。  
如：站务联络、处理请求、管理帮助页。

## 4.2 AD-LOG｜处理记录
作用：把删帖、封号、关闭、转移做成可读的制度性痕迹。  
如：处理日志、审查记录、申诉结果。

## 4.3 AD-TICKET｜处理单 / 请求单
作用：把“某条内容怎么被处理”的过程具体化。  
如：内容处理单、账号状态变更单。

## 4.4 SA-ROOT｜影子档案入口记录
作用：把影子档案作为一个被故意留存的结构首次亮出来。  
如：影子档案目录入口、README。

## 4.5 SA-README｜归档说明记录
作用：让玩家明确“这些不是系统自然残留，是人整理过的”。

## 4.6 SA-ARCH｜差异节选记录
作用：保存被处理内容与公开层之间的关键差异、用户残影与前后对照片段。

## 4.7 SA-LINK｜桥接记录
作用：把影子档案与更深内部层轻微接上。  
如：内部模块名、OA 路径残影、B2 极轻前影。

## 4.8 SA-FRAG｜碎片记录 / 碎片触发结果
作用：承接赵启埋在管理层与影子档案层的异常关键词，触发七碎片中的部分条目。

# 五、这一层的 UI/UX 总规范

## 5.1 管理员边界层视觉
管理员边界层不应该像黑客后台。  
它应该像：
- 老旧但在用的站务页  
- 处理日志系统的简化视图  
- 普通人不太会来，但来了也看得懂表层结构的页面

## 5.2 影子档案层视觉
影子档案层不应该像“酷炫秘密基地”。  
它应该更像：
- 临时目录  
- 差异节选索引  
- 工程师自己给自己看的说明  
- 杂，但有秩序

它的美术核心不是“神秘”，而是：
**有人一边慌，一边仍尽量把东西整理清楚。**

## 5.3 记录头部规范
这一层所有记录都必须有更强的头部结构：
- 记录号  
- 标题  
- 来源路径  
- 记录类型  
- 时间戳 / 状态（按需）

因为这一层开始，玩家需要从“看内容”升级到“看记录结构”。

## 5.4 目录与 README 的规范
目录页与 README 页在这一层非常关键。  
它们承担两件事：
- 防漏页  
- 防信息洪水

所以目录页必须：
- 条目数量少而强  
- 清楚说明哪些内容可见、哪些缺失  
- 能把玩家导向 2–4 条明确的下一步

README 页必须：
- 像给后来者留的话  
- 像工程师写的，不像诗人独白  
- 不可太长，必须短促有力

## 5.5 处理日志页的规范
处理日志不是世界观说明书。  
它的力量来自字段化：
- 时间  
- 对象  
- 类型  
- 状态  
- 备注

字段本身就会让玩家感到：
“这些事是被当成日常工作做掉的。”

# 六、这一层的核心对象冻结

这一层最重要的对象只有六个：

## 6.1 `bbs_admin`
论坛管理节点的公开外壳与后台边缘都围绕它形成。它不是彩蛋，而是管理链可追踪的起点。

## 6.2 `8023`
在这一层，`8023` 必须从“被提及的人”变成“留下结构的人”。

## 6.3 `fswltz`
它要开始承担真正的桥词职责，把人物特征压缩成内部痕迹。

## 6.4 处理记录
这是“制度性压制”成立的关键对象。玩家不必立刻理解全部，但必须开始能读懂字段。

## 6.5 影子档案
这不是一个单条页面，而是一整个“有人故意留档”的事实。

## 6.6 README / 归档说明
这是赵启真正开始说话的地方，但仍然必须像工程师给后来者留的说明，而不是抒情独白。
