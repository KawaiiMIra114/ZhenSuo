# 一、这一层的总目标

这一层只服务一个核心问题：

**谁在系统内部留了路，而这条路是怎么留下来的？**

因此，这一层的所有记录，必须最终服务以下五个结果中的至少一个：

1. 让 `bbs_admin` 从边界词变成管理链节点。  
2. 让 `gh_0314_lx` 的“状态异常”升级成“被后台处理过”。  
3. 让 `8023` 从论坛人物升级成真正碰过后台、留过结构的人。  
4. 让影子档案从猜测升级成真实存在的影子档案系统。  
5. 让玩家第一次摸到更深模块名与 OA 前影，但不直接进入 OA。

任何记录若不能推动以上五点之一，应降级为后续扩张记录，不进入本层主闭环。

# 二、这一层的统一 UI/UX 规则

## 2.1 视觉定位
管理员层与影子档案层不追求“酷炫”，只追求两种气质：
- **制度感**：处理单、处理摘要、状态变更、目录、README 都应有秩序。  
- **人工留痕感**：影子档案不是系统自动历史，而是有人在慌乱中尽量留下来的东西。

## 2.2 不能长成什么样
- 不能长成黑客炫技后台。  
- 不能长成神秘副本传送门。  
- 不能长成世界观百科。  
- 不能比 OA 更解释世界。

## 2.3 记录头部规范
本层所有记录首屏都必须清楚显示：
- 记录号  
- 记录标题  
- 来源路径  
- 记录类型  
- 时间 / 状态（按需）

## 2.4 阅读规则
- 中层记录：首次阅读 30–90 秒内必须拿到一个对象。  
- 深层记录：首次阅读 1–3 分钟内必须拿到一个对象与一个结构变化。  
- 彩蛋 / 碎片记录：首次阅读 15–60 秒内必须让玩家明确“这不是普通记录”。

## 2.5 搜索规则
- 依然只有一个统一搜索框。  
- 本层不新增后台专用搜索框。  
- 搜索命中结果必须更偏向：处理单、状态变更、差异节选记录、目录、README、桥接残语。

## 2.6 页面产物规则
本层每条记录默认仍是 1–3 个关键词：
- 1 个主关键词  
- 1 个支撑关键词  
- 0–1 个余波关键词

## 2.7 防写坏规则
如果一条记录读完后，玩家不能回答“它让哪条处理链或证据链更成立了”，这条记录就是失败记录。

# 三、字段标准（IA 部分）

- **Record ID**：内部编号  
- **Visible Label**：玩家侧标题  
- **Act**：所属阶段  
- **Layer**：管理员边界层 / 处理层 / 影子档案层 / 桥接层 / 碎片层  
- **Content Type**：边界页 / 日志 / 处理单 / 目录 / README / 差异节选记录 / 桥接记录 / 碎片记录  
- **Canon Function**：在世界中的真实作用  
- **Player Function**：对推进的作用  
- **Must Learn**：必须带走的结论  
- **Trigger Terms**：本记录可被哪些词直接或间接命中。
- **Echo Terms**：本记录用于回响、互证或延迟点亮的词；如无则写“无”。
- **Output Terms**：本记录读完后应推动玩家继续搜索、组合或追踪的新词/对象。
- **Prerequisite Action**：前置动作  
- **Entry Paths**：合法入口  
- **Gate Type**：无门 / 软门 / 硬门  
- **Gate Logic**：世界语义  
- **Result Type**：精确命中 / 结果簇 / 折叠 / 查询不足 / 受限投影 / 异常  
- **Cross Links**：关键对照记录  
- **Redundant Path**：冗余链  
- **Emotional Beat**：情绪职责  
- **Mainline Weight**：主线必要 / 主线半必要 / 支撑必要 / 彩蛋  
- **Estimated Read Time**：建议阅读耗时
