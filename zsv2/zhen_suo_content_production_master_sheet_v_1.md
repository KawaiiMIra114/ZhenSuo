# 《镇锁》Content Production Master Sheet v1
## 内容生产总表（从圣经到可制作清单）

> 本文档的职责只有一个：把已经冻结完成的各类 Bible，压缩成**真正可排期、可分工、可逐页落地**的生产总表。  
> 它不再讨论世界观是否成立，也不再讨论结构是否合理。默认前面所有 Bible 均已冻结。  
> 本稿只解决：**先做什么、后做什么、每一页做到什么程度才算合格、哪些页可以后置、哪些页不能动。**

---

# 一、总原则

## 1.1 先做“可跑通”，再做“做厚”
《镇锁》的第一生产目标不是把所有页面一次写满，而是先做出**一条完整可通关的最小闭环路径**。  
换句话说，先保证玩家能从：

**林浩找妹妹 → 诊所官网 → 论坛 → 8023 → 管理员/影子档案层 → OA → 终局执行**

完整跑通，之后再补厚度、冗余、支撑页、彩蛋页与二刷价值。

## 1.2 每条记录必须过四道检查
一条记录只有同时通过以下四项，才允许进入实现阶段：

1. **世界观检查**：不与 Canon / Experience 冲突。  
2. **搜索检查**：至少产出 1 个有效关键词，且能被统一搜索框正确接住。  
3. **结构检查**：它在当前层能回答“这页为什么必须存在”。  
4. **生产检查**：有明确 UI 形态、文案体量、美术需求与上下游依赖。

## 1.3 页面优先级不是按“喜欢程度”，而是按“闭环价值”
优先级只按三档处理：

- **P0：主闭环页**，不做这页主线跑不通。  
- **P1：主线增强页**，不做也能通关，但体验会明显变薄。  
- **P2：支撑 / 彩蛋 / 冗余页**，用于补厚世界、补漏页、防卡关。

## 1.4 不做“页面海”开发
任何层都不允许因为“这个设定很好”就继续加页。  
新增页面必须先回答：

- 它服务哪个闭环？  
- 它产出哪个关键词？  
- 它和哪条记录形成双证据链？

答不上来，就不进总表。

# 二、交付定义（Definition of Done）

每条记录完成，必须至少满足以下条件：

## 2.1 文案完成
- 标题完成  
- 页面正文 / 字段 / 楼层 / 摘要完成  
- 搜索结果标题与短描述完成  
- 关键词埋点完成

## 2.2 结构完成
- 入口路径可达  
- 至少一个合法上游存在  
- 至少一个合法下游存在  
- 相关记录推荐配置完成

## 2.3 UI 完成
- 头部信息齐全  
- 首屏锚点清晰  
- 信息密度符合所属层级  
- 不依赖禁止性交互（hover 唯一路径、热区唯一路径等）

## 2.4 QA 完成
- 关键词能搜到正确结果  
- 与上游记录无冲突  
- 与下游记录可顺接  
- 不 OOC，不穿帮，不抢层级戏份

# 三、建议生产顺序（六阶段）

## Phase 0：系统骨架
先做：
- 统一搜索框逻辑  
- 搜索结果页统一模板  
- 记录头部模板  
- 相关记录模板  
- 0结果 / 折叠结果 / 受限投影记录 / 异常结果模板

这一步不生产剧情页，但不做，后面所有页面都会返工。

## Phase 1：入口 + 官网最小闭环
目标：玩家能稳定拿到 `LX-044-YIN`，并明确知道论坛值得去。

## Phase 2：论坛最小闭环
目标：玩家能稳定追到 `gh_0314_lx`、`8023`、失踪处理机制、管理员边界。

## Phase 3：管理员 + 影子档案最小闭环
目标：玩家明确知道后台有处理链，赵启留了证据并留了路，影子档案真实存在。

## Phase 4：OA 最小闭环
目标：玩家明确知道 DNR 真义、B2 真义、七节点结构、执行接口前影。

## Phase 5：终局层最小闭环
目标：A/B/C 三方案可执行，C 条件判定正确，余波页成立。

## Phase 6：补厚与抛光
补做：
- P1 页  
- P2 页  
- 冗余链  
- 碎片链补全  
- 文案统一  
- 体验节奏校正

# 四、字段说明（总表列）

- **ID**：记录编号  
- **Layer**：所属层  
- **Title**：玩家侧标题  
- **Pri**：P0 / P1 / P2  
- **Tier**：浅层 / 中层 / 深层 / 彩蛋  
- **Function**：这页的核心作用  
- **Depends On**：依赖哪些记录或系统先完成  
- **Trigger Terms**：该页的直接触发词来源；若总表不展开，统一回指对应 IA / 映射表。  
- **Echo Terms**：仅用于回响、互证或延迟点亮的词；如无则写“无”。  
- **Output Terms**：该页必须产出的关键词 / 对象。  
- **Projection Level**：仅允许填写 `公开投影` / `证据投影` / `执行投影`。  
- **UI Form**：页面类型（主题帖 / 日志 / 处理单 / 目录 / 图像等）  
- **Scope**：S / M / L（文案与制作工作量估计）  
- **Asset Need**：文案 / UI / 图像 / 表格 / 特殊模板  
- **Done When**：这一页达到什么条件算可交付
