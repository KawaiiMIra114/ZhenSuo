# 《镇锁》Information Architecture Master Table v2
## Batch 2：论坛层补充版（第三幕前半段）

> 本文档是论坛层的 IA 补充版。  
> 它负责把 Forum Bible v1 中冻结的论坛记录，进一步拆成：入口、关键词、结果类型、回流关系、冗余链、门锁逻辑与玩家获得的认知变化。  
> 本稿不写最终页面文案，只冻结论坛层的结构连接。

---

# 一、Batch 2 的总目标

Batch 2 只服务一个核心问题：

**谁在试图留下证据？**

因此，本批次所有记录都必须围绕以下四个结果之一：
- 让 `gh_0314_lx` 从官网评价残影变成真实用户痕迹  
- 让 `8023` 从数字变成值得追踪的人  
- 让“已处理 / 已折叠 / 已关闭”从个例变成制度  
- 让玩家感觉论坛后面还有更深层的管理与影子档案边界

任何记录如果不能推动以上四点之一，应降级为后续扩张页，不进入 Batch 2 主体。

---

# 二、字段标准（本批次沿用）

- **Record ID**：内部唯一编号  
- **Visible Label**：玩家侧标题/拟真名称  
- **Act**：所属幕次  
- **Layer**：论坛公开层 / 家属层 / 处理层 / 边界层  
- **Content Type**：首页 / 主题帖 / 用户记录 / 搜索结果 / 处理摘要 / 边界页  
- **Canon Function**：它在世界里真实承担的作用  
- **Player Function**：它对玩家推进的作用  
- **Must Learn**：玩家必须从此带走的结论  
- **Trigger Terms**：本记录可被哪些词直接或间接命中。
- **Echo Terms**：本记录用于回响、互证或延迟点亮的词；如无则写“无”。
- **Output Terms**：本记录读完后应推动玩家继续搜索、组合或追踪的新词/对象。
- **Prerequisite Action**：来到这里前要完成什么  
- **Entry Paths**：进入本记录的合法路径  
- **Gate Type**：无门 / 软门 / 硬门  
- **Gate Logic**：门在世界里的语义  
- **Result Type**：精确命中 / 结果簇 / 折叠 / 查询不足 / 受限投影 / 异常  
- **Cross Links**：关键对照记录  
- **Redundant Path**：备用发现路径  
- **Emotional Beat**：情绪职责  
- **Mainline Weight**：主线必要 / 主线半必要 / 支撑必要 / 扩张  
- **Estimated Read Time**：建议阅读耗时

# 四、论坛层最小闭环检查

## 4.1 最小主线闭环
玩家只要完成以下链条，论坛层最小闭环就成立：
1. 进入 FR-HUB-01  
2. 命中 `gh_0314_lx` 相关记录  
3. 命中 `8023` 首次成形记录  
4. 搜“失踪”看到 FR-SUP-01  
5. 看到管理员/处理机制的边缘存在感

## 4.2 论坛层结束时玩家必须至少带走这四样中的三样
- `gh_0314_lx` 是林晓论坛痕迹  
- `8023` 是关键人  
- 失踪类讨论会被处理  
- 管理员/影子档案边界存在

## 4.3 本批次不允许出现的断点
- 玩家知道论坛存在，但论坛首页没有可抓对象  
- `gh_0314_lx` 只是一页怀旧资料，没有新方向  
- `8023` 只出现一次，像硬塞线索  
- “失踪”搜索是纯空白  
- `福生无量天尊` 第一次出现就像密码讲解  
- `bbs_admin` 仍然只有源码单点在支撑
