# 一、OA层到底负责什么

OA层不是一个更复杂的网站，也不是奖励玩家的终极资料库。  
它在《镇锁》里的任务，是完成以下六件事：

## 1.1 把“后台处理链”翻成“工程系统链”
管理员层和影子档案层已经证明：
- 这里有人在删帖  
- 有人在做状态变更  
- 有人在留证据

OA层要再推进一步：
**把这些处理、转移、关闭，翻成一整套工程系统的表层接口。**

也就是说，玩家在这一层第一次感到：
- 这不是站务异常  
- 这是一台真正的机器，在拿人做事

## 1.2 把 DNR 从公开医疗词，翻成剥壳程序
前面所有层都在让 DNR 看起来像：
- 睡眠疗法  
- 临床流程  
- 高端治疗方案

OA层必须让玩家明确知道：
**DNR 在内部语境中不等于公开语义。**

## 1.3 把 B2 从“机房/受限区域”翻成节点矩阵
论坛和影子档案层可以给玩家 B2 前影，但不能给真义。  
OA层是第一次必须把以下事实钉住的地方：
- B2 不是单纯机房  
- 节点、液冷、维护、负载、响应，不只是设备词  
- 这里在压榨意识、维持运算、支撑更高层接口

## 1.4 把赵启从留证据/留路的人，翻成留下反制结构的人
README 与影子档案证明了：
- 赵启在留路  
- 他不是纯情绪性留言者

OA层必须让玩家第一次看见：
**赵启不是只在存档，他在拆机器。**

## 1.5 把七碎片从“散落的异常页”翻成“七节点反制系统”
碎片在前面可以作为异常页触发，但到 OA 层，玩家必须开始理解：
- 七不是象征装饰  
- 七是工程与仪式双重需要  
- 缺一不可

## 1.6 把 TaiYi / JiuKu 从前影，翻成可组装的执行语义
OA层不能直接进入终局执行。  
但它必须让玩家到本层末尾时知道：
- `JiuKu` 是什么级别的对象  
- `TaiYi` 为什么会反复回响  
- 二者不是谜语，而是执行结构的两个部件

# 二、OA层的体验定位

## 2.1 体验定位一句话
OA层是《镇锁》的**系统真相层**。

它的重点不是“更恐怖”，而是“更冷”。  
前面几层靠的是：
- 人的声音  
- 处理痕迹  
- 被删掉的内容

到了 OA 层，玩家要第一次感到：
**这里的恐怖不靠鬼话，而靠字段、模块、审批、日志和图像。**

## 2.2 这一层的核心问题
这一层只能围绕一个问题组织：

**地下真正运行的东西，到底是什么？**

不是“我现在要怎么通关”，那是下一层。  
不是“Meridian 背后还有什么”，那也不是这一层。  
OA层的重点是：
- 机器怎么运作  
- 人怎么被接入机器  
- 机器怎么被赵启试图拆掉

## 2.3 玩家感受目标
玩家应从：
- 看处理链
过渡到：
- 看系统字段
再过渡到：
- 看反制结构

也就是说，视角从“调查员”进一步变成“在拆一套内部系统的人”。

# 三、总语法与交互规则

OA层依然服从**统一搜索框**。  
不新增“OA 专属第二搜索框”。

## 3.1 允许的动作
- 搜索模块名  
- 打开模块索引  
- 阅读采购 / HR / 维护 / B2 / 图像 / 备注等记录  
- 对照时间、物料、处理对象、节点编号  
- 触发异常关键词进入碎片记录  
- 顺着模块与记录下潜

## 3.2 不允许的动作
- 用随机密码硬闯 OA  
- 靠复杂命令行输入推进  
- 靠 hover 找唯一真相  
- 把 OA 写成后台 UI 大拼盘  
- 把所有真相一次性塞在某份长报告里

## 3.3 本层信息密度原则
OA层是目前信息密度最高的一层，但仍然必须遵守：
- 一条记录只解决一个局部系统问题  
- 复杂系统通过多条记录互相对照成立  
- 不允许单页百科化

## 3.4 本层记录产物规则
仍遵守 1–3 个关键词规则：
- 1 个主关键词  
- 1 个支撑关键词  
- 0–1 个余波关键词

但本层允许：
- 关键词更偏技术/系统词  
- 字段更重  
- 记录之间的对照关系更强

# 四、OA层记录类型

OA层只使用以下九类记录：

## 4.1 OA-HUB｜模块索引记录
作用：给玩家一张清晰的内部系统地图，但不剧透全部内容。

## 4.2 OA-PROC｜采购 / 物料记录
作用：让不该出现在医疗机构的材料以工程语言出现，制造第一层系统裂口。

## 4.3 OA-HR｜人事 / 转移 / 事故相关记录
作用：把人当资源处理的痕迹，与前面的新闻、失联、离职线回流。

## 4.4 OA-MNT｜维护日志记录
作用：让 8023、fswltz、夜班、节点异常、系统抖动真正对上。

## 4.5 OA-DNR｜术语 / 说明记录
作用：把 DNR 从公开治疗语义翻成内部程序语义。

## 4.6 OA-B2｜B2 报告 / 节点记录
作用：让地下区域的真实职责成立。

## 4.7 OA-IMG｜图像 / 示意记录
作用：让文字真相有形状，让七节点和系统结构可被直观看见。

## 4.8 OA-NOTE｜系统备注 / 临时说明记录
作用：承接 TaiYi / JiuKu 前影，提供冷而短的解释残片。

## 4.9 OA-FRAG｜碎片记录
作用：在 OA 层继续承接异常关键词，形成七碎片更硬的一部分。

# 五、OA层的视觉与 UI/UX 总规范

## 5.1 视觉定位
OA层不是未来科技仪表盘。  
它应该是：
- 机构内部正在使用的功能页  
- 审批系统 / 日志系统 / 资料系统的拼接结果  
- 够真实、够冷、够普通

## 5.2 不能长成什么样
- 不能是黑客电影后台  
- 不能是赛博 UI  
- 不能是“恭喜你进入最终区域”的游戏关卡

## 5.3 页面头部规范
本层所有记录首屏必须明确：
- 记录号  
- 模块名 / 文档名  
- 来源路径  
- 时间或版本（按需）  
- 状态/对象（按需）

## 5.4 字段化原则
OA层的震撼力很大程度来自字段化：
- 对象  
- 状态  
- 模块  
- 时间  
- 备注  
- 负载 / 节点 / 审批项

也就是说，尽量让字段自己讲话，而不是作者替字段解释。

## 5.5 模块索引页规范
OA-HUB 页必须做到：
- 给出模块地图  
- 告诉玩家这里不是无限深  
- 让玩家知道先看哪几个模块最值钱  
- 不出现“全部展开”的诱惑

## 5.6 图像记录规范
图像记录不能炫技。  
它的作用是把文字里已经存在的东西“具象化”，不是另起一套暗号。

## 5.7 备注页规范
系统备注页必须短、冷、半解释。  
它不负责完整说明，只负责让散落前影开始组装。
