# 一、文档职责

本稿只解决一个核心问题：

**《镇锁》的“统一搜索框”到底意味着什么，记录如何被触发，深层对象如何显露而不写成搜索引擎，终局输入如何执行而不破坏半 ARG 语法。**

因此，本稿负责冻结：

1. 搜索框的真实职责。  
2. 关键词模型。  
3. 记录触发模型。  
4. 单记录 / 结果簇 / 受限投影 / 查询不足 / 异常命中等反馈类型。  
5. 裸词与组合词的命中差异。  
6. 影子档案的表现原则。  
7. 终局层输入语义。  
8. 各层下位文档必须遵守的边界。

# 二、最上位定义

## 2.1 全游戏只有一个统一搜索框
这条保留，不再动。  
玩家从头到尾只学一种主语法：

**阅读记录 → 发现词 → 在同一个搜索框中输入 → 新记录出现。**

无论玩家当前处于：
- 入口层  
- 官网层  
- 论坛层  
- 管理员层  
- 影子档案层  
- OA 层  
- 终局层

可见输入面都必须是同一个搜索框。

## 2.2 但全游戏不是一个统一搜索引擎
这是本稿最重要的修正。  
《镇锁》不能被写成：
- 通用全文搜索系统  
- 全库召回系统  
- 分阶段自动增厚的统一检索后端

更准确的定义是：

## 2.3 《镇锁》是“统一搜索框 + 关键词触发网络”
也就是说：
- 玩家体验上是在“搜索”  
- 设计实现上是在“用关键词触发记录”

所以《镇锁》的搜索模型不是：
### 搜数据库
而是：
### 拉出预先定义好的记录投影

## 2.4 搜索的本质是“触发记录”，不是“检索数据库”
从本稿生效后，所有下位文档都必须按这个定义回写：

- 搜索框是唯一输入面  
- 记录是否出现，取决于该输入是否命中该记录的触发词集合  
- 系统不需要也不应表现为一个全知的通用搜索引擎

# 三、关键词模型（正式冻结）

本稿统一废止所有模糊的“Searchable Terms”口径。  
以后每条记录，必须明确区分以下三类词。

## 3.1 Trigger Terms（触发词）
### 定义
真正能把某条记录拉出来的词。

### 规则
- 每条记录默认 1–3 个 Trigger Terms  
- 高密度记录可超过 3 个，但必须有主次  
- Trigger Terms 必须可解释：为什么这个词会触发这页  
- 禁止一页拥有大量泛化触发词，导致全库像搜索引擎

### 例子
- `LX-044-YIN` → 查询异常页  
- `gh_0314_lx` → 论坛用户记录  
- `8023 维护日志` → OA 维护日志  
- `TaiYiJiuKu` → 终局 C 执行页

## 3.2 Echo Terms（回响词）
### 定义
这页中出现、值得记住、会在别处再次发响的词。

### 规则
- Echo Terms 不一定能直接命中本页  
- Echo Terms 主要用于建立回流、互证、延后点亮  
- Echo Terms 不能被误写成“看见了就一定能搜出新页”的保证对象

### 例子
- 早期专栏里的 `TaiYi`  
- 论坛里早期的“福生无量天尊”  
- 页脚中的 Meridian

## 3.3 Output Terms（产出词）
### 定义
玩家读完这页后，最值得拿去继续输入的词。

### 规则
- 每页至少 1 个 Output Term  
- Output Term 可以与 Trigger Term 重合，也可以不同  
- Output Term 必须服务“下一步该做什么”的清晰性

## 3.4 记录必须三分法写清
从本稿生效后，所有下位文档中的记录表必须至少包含：
- Trigger Terms  
- Echo Terms  
- Output Terms

不再允许用一个模糊字段把三者混写。

# 四、命中模型（正式冻结）

## 4.1 默认命中形态 = 单记录触发
《镇锁》的默认搜索返回，不是结果簇，而是：

**单记录命中。**

也就是说，玩家输入合适关键词时，默认应该拉出：
- 一条主记录
而不是：
- 一整页像搜索引擎那样的结果列表

## 4.2 结果簇是特例，不是常态
结果簇只允许用于以下场景：
- 论坛层多点回响对象（如 `8023`）  
- 家属区这类群体对象  
- 某些处理摘要层  
- 目录型 / 索引型页面

除了这些情况外，普通记录应优先写成单记录触发。

## 4.3 裸词与组合词
这是本稿的关键边界模型。

### 裸词（Bare Term）
如：
- `8023`  
- `DNR`  
- `B2`

默认只应拉出：
- 公开投影  
- 目录投影  
- 边缘存在感  
- 外层结果簇

### 组合词（Composed Term）
如：
- `8023 维护日志`  
- `gh_0314_lx 状态变更`  
- `B2 节点负载`  
- `DNR 内部释义`

允许拉出：
- 证据投影  
- 处理单  
- 备份证据页  
- 模块说明  
- 更深层具体记录

## 4.4 本作不使用显式权限门，使用“问题门”
《镇锁》不引入：
- 进度条  
- 章节锁  
- 显式权限等级  
- “必须先过 A 点才能进 B 点”的硬端点锁

本作真正的边界，是：

**你问得够不够具体。**

这不是能力门，而是问题门。

# 五、记录投影模型

同一对象可以有不同投影层。  
本稿统一冻结为三类。

## 5.1 公开投影（Public Projection）
玩家最早看到的外层记录。  
包括：
- 官网公开页  
- 论坛公开帖  
- 普通索引页  
- FAQ / 首页 / 目录页

## 5.2 证据投影（Evidence Projection）
更深层的、带处理痕迹或对照价值的记录。  
包括：
- 处理单  
- 处理摘要  
- 备份证据页  
- 内部模块说明  
- 差异节选页

## 5.3 执行投影（Execution Projection）
不再服务“知道更多”，而服务“做什么”。  
只存在于终局层，承载：
- 执行说明  
- 执行接口  
- A/B/C 方案  
- 余波页

## 5.4 投影差异不是权限门
深浅差异来自：
- 词是否足够具体  
- 输入是否命中更深 Trigger Terms  
- 当前输入处于搜索触发还是执行触发

不来自：
- 账号等级  
- 显式权限位  
- 隐形进度条

# 六、反馈类型（正式重写）

本稿废止“权限结果”作为常规主反馈类型。  
以后只允许以下五种主反馈。

## 6.1 单记录命中
默认主反馈。  
适用于绝大多数记录。

## 6.2 结果簇
只在多点回响对象层使用。  
不能被泛化成默认返回。

## 6.3 受限投影记录
这是替代旧“权限结果”的主要方式。

### 定义
玩家没有直接拉出最深原件，而是拉出了该对象的：
- 摘要页  
- 残影页  
- 目录页  
- 处理后版本  
- 差异节选页

### 意义
- 不直接确认“你没权限”  
- 不把系统写成对象枚举 oracle  
- 仍然保留调查到更深对象边缘的感觉

## 6.4 查询不足结果
这是替代“权限不足确认对象存在”的第二种关键反馈。

### 定义
当前输入不足以定位单条记录。

### 推荐语气
- 当前索引范围内未形成稳定命中  
- 关键词过宽，建议补充对象语境  
- 当前检索结果不足以定位单条记录

### 禁止语气
- 已识别到该对象，但当前权限不足  
- 请求已记录  
- 需更高权限

## 6.5 异常命中
保留，但收窄职责。  
只用于：
- 异常关键词  
- 碎片触发  
- 少量系统抖动页

异常命中不得泛滥成通用边界反馈。

# 七、影子档案规则（正式冻结）

## 7.1 影子档案不是 raw backup
这一条必须写死。  
影子档案在设定上不再被定义为：
- 系统冷备  
- 可完整恢复的原始备份库  
- 删除前原文仓库

## 7.2 影子档案 = 赵启整理过的证据包
也就是说，影子档案只能表现为：
- 差异节选  
- 前后对照片段  
- 不完整快照  
- 被重排和注释过的证据结构

## 7.3 禁止的写法
从本稿生效后，所有影子档案类页面禁止写成：
- 完整被删帖子恢复  
- 完整处理前原文快照  
- raw dump 视图

## 7.4 允许的写法
允许写成：
- 处理前差异节选  
- 备份证据片段  
- 引用节选  
- 注释化保留页  
- 带缺损的证据包

## 7.5 设计目标
既保留：
- “公开层不是原貌”的叙事力量

又避免：
- 真正意义上的备份泄露语义

# 八、敏感字段暴露规则

本作虽然不是现实产品，但规格层仍需遵守“最小必要泄露”原则。

## 8.1 时间精度
默认显示到：
- 日  
- 时间窗

只有当分钟级信息是主线推理必要时，才允许精确到分钟。

## 8.2 用户状态
默认只给：
- 可理解的分桶状态  
如：不可用、已关闭、迁移中、处理中

不优先暴露细粒度内部状态码。

## 8.3 HR / 流转 / 异常离岗
只展示：
- 主线必要的事实轮廓  
- 与已知对象的对照点

不展示过度可重识别的细节集合。

## 8.4 跨页可拼接字段
任何能与其他页面一起拼成完整身份轨迹的字段，都必须先证明其主线必要性，才允许保留。

# 九、终局输入规则（正式冻结）

## 9.1 终局层仍然只有一个搜索框
这一点保留。

## 9.2 但终局层输入不再属于普通搜索
一旦玩家进入终局执行接口页：
- 同一个搜索框的语义切换为：
### 执行触发（Execution Trigger）

不再属于：
### 普通搜索触发（Discovery Trigger）

## 9.3 三类执行对象
### `烈火`
触发 A 方案记录。

### `替换` / `上行`（以最终定稿词为准）
触发 B 方案记录。

### `TaiYiJiuKu`
若结构完整，触发 C 方案记录；  
若结构不完整，触发“结构未闭合”记录。

## 9.4 为什么不再需要额外的双系统
因为本稿已经明确：
- 搜索框可见层统一  
- 语义层可区分为搜索触发与执行触发

这既保住了：
- 单搜索框  
- 单主语法  
- 无新玩法

又避免了：
- 查询与执行混层

# 十、各层强制修订指令

## 10.1 官网层
- 查询页默认写成单记录命中  
- `LX-044-YIN` 可保留异常命中  
- 删除“权限结果”式对象确认

## 10.2 论坛层
- `8023`、家属互助、失踪处理可以使用结果簇  
- 普通帖、用户页、公告页应以单记录命中为主  
- `福生无量天尊` 先是 Echo Term，再压缩成 Bridge Trigger Term

## 10.3 管理员 / 影子档案层
- 裸词不再直达最深内部原件  
- 优先返回受限投影记录  
- 所有“处理前快照/前版本”口径要改成证据包口径

## 10.4 OA 层
- `OA`、`B2`、`DNR` 裸词优先返回索引或浅层说明  
- 组合词再拉模块级深层记录  
- 不再用“权限不足”确认内部对象存在

## 10.5 终局层
- 执行层输入进入执行触发模式  
- 不再属于普通搜索  
- C 条件不足时返回“结构未闭合”，不返回权限页

## 10.6 生产总表
所有生产表字段中的：
- Searchable Terms

必须被拆成：
- Trigger Terms  
- Echo Terms  
- Output Terms

# 十一、写坏判定

如果未来任何文档出现以下情况，就说明又偏回旧问题了：
- 把《镇锁》写成统一搜索引擎  
- 大量记录默认一搜就是结果簇  
- 裸词频繁直达内部原件  
- “权限不足”再次成为对象发现手段  
- 影子档案重新被写成 raw backup  
- 终局输入重新被当成普通搜索  
- 记录没有明确区分 Trigger / Echo / Output Terms

# 十二、冻结结论

《镇锁》的搜索、触发与边界模型正式冻结为：

- 全游戏只有一个统一搜索框  
- 搜索不是通用检索，而是关键词触发记录  
- 记录必须区分 Trigger Terms、Echo Terms、Output Terms  
- 默认命中形态是单记录，不是结果簇  
- 结果簇只用于少数多点回响对象层  
- “权限结果”不再作为主反馈  
- 更深对象通过组合词与受限投影记录显露  
- 影子档案是赵启的证据包，不是系统冷备  
- 终局层输入属于执行触发，而不是普通搜索  
- 全作不引入进度条，不引入显式权限门，不引入多搜索系统

本稿之后，任何 Bible、IA、Page Bible 或 Production Sheet 若与本稿冲突，都必须回写修订。
