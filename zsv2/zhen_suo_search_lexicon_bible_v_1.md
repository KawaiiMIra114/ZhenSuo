# 《镇锁》Search Lexicon Bible v1 ~~（历史稿）~~
## 统一搜索框与关键词流动圣经

> 本文档负责冻结《镇锁》的**搜索语法、关键词分级、搜索结果规则、词与词之间的流动关系**。  
> 它不负责解释底层世界观，也不负责直接书写页面文案。  
> 它的作用是保证：玩家看到一个词时，知道这个词为什么值得搜；搜了以后，得到的不是随机回报，而是符合当前阶段、符合心理预期、符合世界逻辑的结果。

---

# 一、文档职责

本作重构后的核心推进手段不是窗口切换、谜题装置或隐藏热区，而是：

**阅读记录 → 发现关键词 → 在统一搜索框中搜索 → 打开新记录 → 形成回流 → 再次搜索。**

因此，Search Lexicon Bible 负责回答以下问题：

1. 哪些词是主线词，哪些词只是扩张词或彩蛋词。  
2. 一个词第一次应该在哪里出现。  
3. 玩家在不同阶段搜同一个词，为什么会得到不同层级的结果。  
4. 0 结果、折叠结果、受限投影记录、查询不足结果、异常结果分别应该怎么写。  
5. 搜索结果如何把玩家温和但明确地推向下一个对象。  
6. 七枚碎片用什么样的“异常关键词”触发才既合理又不生硬。  
7. 如何让搜索本身成为调查行为，而不是答案自动售卖机。

---

# 二、总原则冻结

## 2.1 全游戏只有一个搜索框
《镇锁》全流程只有一个统一搜索入口。  
玩家无论当前处于：
- 入口整理页  
- 官网记录  
- 论坛记录  
- 影子档案  
- OA 记录  
- 外部世界记录

执行“搜索”这个动作时，调用的都必须是同一套搜索系统。

### 设计目的
- 统一玩家行动语法  
- 强化“关键词就是武器”的体验  
- 避免不同系统各有一套搜索逻辑导致学习成本膨胀  
- 迫使每条记录都真正产出可搜索对象

## 2.2 唯一的是入口，不是结果风格
只有一个搜索框，不意味着所有结果长得一样。  
搜索结果仍必须保留来源差异：
- 官网条目应像官网结果  
- 论坛记录应像论坛结果  
- 内部文件应像文件记录  
- OA 结果应像审批/报告/日志  
- 碎片结果应像异常弹出页或隐藏记录页

**搜索入口统一，结果皮肤分层。**

## 2.3 不做显式进度条
本作不允许任何显式进度条，包括：
- 百分比完成度  
- 主线章节进度 UI  
- 收集完成条  
- “你还差几页”的提示框

允许保留的只有：
- 记录号  
- 来源路径  
- 搜索结果簇  
- 模块结构  
- 索引页  
- 相关记录推荐

本作追求的是**调查地图感**，不是通关进度感。

## 2.4 每条记录默认产出 1–3 个关键词
每条记录默认必须产出 1–3 个可带走关键词。  
允许个别高密度深层记录超过 3 个，但必须满足：
- 主线强关键词最多 1–2 个  
- 其余为扩张词、余波词、回流词  
- 不得出现 5 个以上等权重关键词并列争抢玩家注意力

## 2.5 关键词必须分主 / 次 / 余波
每条记录内的关键词应至少按以下逻辑区分：

### 主关键词
这一页最希望玩家带走的对象。通常只有 1 个。

### 次关键词
与主关键词形成解释、补充、对照。通常 1 个。

### 余波关键词
此刻未必立刻使用，但后续会回流点亮。通常 0–1 个。

## 2.6 搜索不是万能透视
统一搜索框不是全知全开的神谕系统。  
同一个词在不同阶段的结果必须符合：
- 当前可见层级  
- 玩家已知上下文  
- 该系统本身的访问边界  
- 赵启后门污染造成的局部泄露程度

玩家可以早早搜到某些词，但通常只会先看到“这一层看得见的部分”。

# 三、关键词的四级分类

## 3.1 主线词（Mainline Terms）
### 定义
直接推动主线推进、层级下潜或关键角色成形的词。

### 使用规则
- 每幕必须有少量主线词  
- 主线词首次出现必须稳定、清晰、可复查  
- 主线词搜索结果必须带来新的行动方向

### 例子
- 林晓  
- 安宁深眠  
- LX-044-YIN  
- gh_0314_lx  
- 8023  
- bbs_admin  
- PHX-ALPHA  
- fswltz  
- JiuKu  
- TaiYi

## 3.2 碎片词（Fragment Terms）
### 定义
指向七枚碎片或赵启故意埋藏的异常触发关键词。

### 使用规则
- 不得在首次出现时写得像“答案在这里”  
- 必须先作为异常措辞、技术残留、无意义词出现在正常文档里  
- 被玩家主动带去搜索时，才弹出碎片记录

### 例子
- 由赵启嵌入维护日志、图像备注、论坛残影、文档尾注的异常词

## 3.3 扩张词（Expansion Terms）
### 定义
扩张世界、资本层、地理层、余波层，但不承担单幕唯一推进。

### 使用规则
- 可以较早投影  
- 不应在第一次命中时过度抢主线氧气  
- 搜索结果可先较薄，再在后期增厚

### 例子
- Meridian  
- Project Delta  
- 安宁路  
- 南郊区信号  
- 线香味  
- 王总

## 3.4 冗余词 / 背景词（Support Terms）
### 定义
服务于冗余链、真实感、补漏，不单独承担关键节点。

### 使用规则
- 可帮助卡关玩家绕回主线  
- 允许返回较短结果  
- 不能让玩家长期滞留在无推进的信息泥潭里

### 例子
- 康复关键期  
- 暂不探视  
- 神经可塑性  
- 深度康复阶段  
- 患者服务中心

# 四、搜索结果的六种标准类型

## 4.1 精确命中结果（Exact Result）
### 定义
玩家输入的词直接命中一条明确记录。

### 适用场景
- 人名已成为可追对象  
- 用户 ID  
- 档案编号  
- 内部文件名

### 文案气质
明确、克制、像真实系统返回。

### 设计要求
- 页面顶部必须明确告诉玩家命中了什么  
- 结果不应被大量无关项稀释  
- 应产生下一个对象

## 4.2 相关结果簇（Related Cluster）
### 定义
输入一个词，返回 2–4 条彼此有关联的记录，而不是单条直达。

### 适用场景
- 论坛搜索  
- 家属讨论  
- 多处提及的异常词  
- 同一对象的多层残影

### 文案气质
“你碰到了一个有回响的对象。”

### 设计要求
- 结果必须有主次顺序  
- 第一条结果最适合当前阶段理解  
- 次级结果负责补漏和扩张

## 4.3 0 结果（Zero Result）
### 定义
系统不给出公开命中，但 0 结果本身必须有信息价值。

### 适用场景
- 词存在，但当前公开层不该给你  
- 这个对象被处理过  
- 你已靠近折叠层/权限层边缘

### 文案气质
冷、正常、略带行政性；不要写成“你猜对了但我不告诉你”。

### 设计要求
0 结果页至少承担以下之一：
- 暗示有折叠结果  
- 暗示此词曾被处理  
- 暗示当前词属于内部标签  
- 暗示换一个更具体的词会更有效

## 4.4 折叠结果（Suppressed Result）
### 定义
系统承认有内容，但默认不完全公开，仅给出残影、摘要、处理痕迹或折叠入口。

### 适用场景
- 论坛删帖  
- 敏感关键词  
- 被压制的家属内容  
- 赵启留下但未被完全清除的记录

### 文案气质
像正常内容审核系统，而不是故意装神秘。

### 设计要求
- 玩家必须知道“这里本来有内容”  
- 不一定立即让玩家读全，但必须留下抓手  
- 是通往更深层的软门，不是死路

## 4.5 受限投影记录（Restricted Projection）- 替代已废弃的"权限结果"
### 定义（按RTB Bible line 255-269）
系统识别了这个对象，但只给出该对象的摘要页/残影页/目录页/处理后版本/差异节选页。

### 适用场景
- PHX-ALPHA（只给内部标签摘要，不确认完整权限）
- 内部模块名（只给引用边界）
- 管理员关键词（只给站务入口）
- 某些 OA 条目（只给投影）

### 设计要求
- 不能确认对象存在（禁止对象枚举oracle）
- 只给摘要/残影/目录页/处理后版本
- 反馈"查询不足"或类似工程语义

### 禁止
- "请求已记录"
- "需更高权限"
- "权限不足确认对象存在"

## 4.6 查询不足结果（Insufficient Query）
### 定义（按RTB Bible line 271-286）
当前输入不足以定位单条记录。

### 适用场景
- 关键词过宽
- 对象语境不明
- 系统需要更多组合

### 推荐反馈
- "当前索引范围内未形成稳定命中"
- "关键词过宽，建议补充对象语境"

## 4.7 异常结果（Anomalous Result）
### 定义
这个词本身会干扰系统渲染、索引或表层逻辑。

### 适用场景
- LX-044-YIN  
- 林晓信号溢出  
- 碎片触发异常词  
- 某些接近 B2 真相的被污染对象

### 文案气质
不是廉价故障特效，而是“系统在处理这个对象时露了一下底”。

### 设计要求
- 异常必须短促、可读、可记住  
- 不可演得太满  
- 异常后的返回内容仍要能导向下一步

# 五、玩家搜索时的心理状态模型

每个词不仅要定义“会返回什么”，还要定义：**玩家在搜它时心里以为自己在做什么。**

## 5.1 好奇型搜索
### 心理
“这个词有点怪，我想看看是什么。”

### 适用词
- 医疗术语  
- 机构名  
- 轻微异常的用户 ID  
- 新闻地名

### 结果设计原则
- 不要一次给太深  
- 要让玩家觉得“继续搜是值得的”

## 5.2 验证型搜索
### 心理
“我怀疑这个对象和前面那件事有关，我来证实一下。”

### 适用词
- 林晓  
- LX-044-YIN  
- gh_0314_lx  
- 8023

### 结果设计原则
- 应提供较高确定性回报  
- 要让玩家感觉自己的怀疑是被系统接住的

## 5.3 试探型搜索
### 心理
“这个看起来像内部词，我不确定有没有用，但想试试。”

### 适用词
- PHX-ALPHA  
- bbs_admin  
- 某些异常拼写  
- 赵启残语

### 结果设计原则
- 应给出“你碰到了边界”的反馈  
- 不能直接彻底白给  
- 不能又冷又空到让玩家怀疑自己瞎试

## 5.4 回流型搜索
### 心理
“这个词我之前见过，现在我有新上下文了，回来再搜一次。”

### 适用词
- 安宁路  
- Meridian  
- 林德坤  
- JiuKu  
- TaiYi

### 结果设计原则
- 与早期结果相比，应出现明显增厚  
- 让玩家感到“旧词被点亮了”

## 5.5 冲刺型搜索
### 心理
“我知道这和终局相关，我现在在试着把东西拼起来。”

### 适用词
- TaiYi  
- JiuKu  
- TaiYiJiuKu  
- 七碎片相关异常词

### 结果设计原则
- 要慎重  
- 不能让终局词在没有准备的情况下变成早期彩蛋  
- 必须和阶段深度绑定

# 七、0 结果、折叠结果、受限投影记录、查询不足结果的文案规范

## 7.1 0 结果文案规范
### 必须避免
- “未找到任何结果。”然后什么都没有  
- 明显像系统在阴阳怪气地暗示你  
- 过长解释导致像作者出场

### 推荐结构
- 系统性一句话  
- 处理状态一句话  
- 若有必要，给一个很弱的方向性句子

### 示例逻辑
- 当前公开索引中未找到相关条目。  
- 该关键词可能涉及已归档、已迁移或受限内容。  
- 建议缩小搜索范围或使用更具体对象。

## 7.2 折叠结果文案规范
### 必须避免
- “这里有秘密哦”式表达  
- 夸张的红色警告框  
- 让玩家完全不知道这是删帖还是没加载出来

### 推荐结构
- 条目存在  
- 当前状态：折叠 / 已处理 / 不对外公开  
- 可见摘要或引用残影

## 7.3 受限投影记录文案规范（本规范替代已废弃的"权限结果"）
### 必须避免
- "权限不足确认对象存在"式表达
- 让玩家通过反馈确认深层对象存在（对象枚举oracle）

### 推荐结构（按RTB Bible line 255-269）
- 受限投影记录：只给出摘要页/残影页/目录页/处理后版本/差异节选页
- 查询不足结果：当前输入不足以定位单条记录，建议补充对象语境
- 禁止使用"请求已记录"、"需更高权限"的表述

## 7.4 异常结果文案规范
### 必须避免
- 大量乱码轰炸  
- 纯特效无语义  
- 故障动画抢走可读信息

### 推荐结构
- 异常短促发生  
- 留下 1–2 个可记住的技术/渲染残语  
- 仍让玩家能继续动作

# 八、关键跳转节点的冗余原则

## 8.1 关键事实必须两种表达
同一关键事实至少用两种形态出现：
- 一次叙事词  
- 一次可复制名词

### 例如
“林晓的公开痕迹被处理过”必须同时由：
- 一条评价中的异常感  
- `gh_0314_lx` 这个可直接复制搜索的用户 ID

## 8.2 关键词不能只来自一个系统
若某词是关键跳转节点，尽量做到至少两条路径：
- 直接首次出现路径  
- 回流确认路径

### 例如
`PHX-ALPHA` 可以来自：
- 档案查询异常结果  
- 论坛 / 内部文件中的再出现

## 8.3 10 分钟内必须得到一次“异常搜索回报”
玩家在游戏开始后 10 分钟内，至少要搜出一次与普通结果明显不同的内容。  
这条异常结果不必讲透，但必须让玩家确认：
**这个系统真的有问题。**

# 九、七枚碎片的搜索触发原则

## 9.1 基本规则
七枚碎片不再通过系统提示、热区、滚到底等方式触发。  
它们统一改为：
- 赵启在七条不同记录中埋下异常关键词  
- 这些词第一次看上去像技术残留、错字、无意义缩写、注释尾巴或不合语境的孤词  
- 玩家主动复制或记下这个词去搜索  
- 搜索结果页弹出“碎片记录”

## 9.2 异常关键词的设计红线
- 看上去不能太像“作者塞答案”  
- 不能与正常中文表意完全无关到离谱  
- 最好兼具技术口吻和个人口吻的裂缝感  
- 与赵启身份一致：工程师式、维护式、低调、不抒情

## 9.3 碎片结果页规范
碎片页不是神秘动画，而是一条异常记录：
- 顶部明确为异常命中  
- 中部是碎片内容  
- 底部仍要产出一个新的词、一个新的人、或一个新方向

## 9.4 碎片词与主线词的关系
碎片词不应长期悬空。  
至少有一半碎片词必须与主线词存在清晰连接：
- 指向赵启  
- 指向 B2  
- 指向林德坤  
- 指向 TaiYi/JiuKu  
- 指向七节点

# 十、搜索结果页的组织规范

## 10.1 标准结构
统一搜索结果页建议包含：
1. 搜索框本体  
2. 本次关键词显示  
3. 结果分类区  
4. 主结果  
5. 相关结果  
6. 处理痕迹 / 折叠痕迹 / 权限说明（按需）

## 10.2 结果排序原则
排序优先级不是“世界观最深”，而是：
1. 当前阶段最可理解  
2. 当前阶段最能推进  
3. 当前阶段最适合补漏  
4. 再之后才是扩张和深层阴影

## 10.3 相关结果的作用
相关结果不是为了凑数量。  
它的作用是：
- 防漏页  
- 建回流  
- 告诉玩家这个词在别处也响过

## 10.4 搜索后的下一步必须清晰
每次搜索后，玩家都应尽量能回答：
**我现在最值得再搜哪个词？**

若搜索结果不能自然导向下一词，该词要么写坏了，要么当前阶段放错了。

# 十二、搜索系统的失败判定

一个搜索系统写坏，通常会表现为：
- 玩家搜一个词，结果要么太空，要么太满  
- 玩家搜完后不知道下一个词是什么  
- 不同词返回的结果语气完全不同，像不同作者写的  
- 0 结果没有任何价值  
- 受限投影反馈像游戏锁而不是机构锁（已禁用此类型）  
- 主线词与扩张词在首回报里权重相同

本 Bible 的作用，就是从根部防止这些问题发生。

# 十四、冻结结论

《镇锁》的搜索语法正式冻结为：

- 统一搜索框  
- 分层结果皮肤  
- 每条记录 1–3 个关键词  
- 关键词分主线、碎片、扩张、冗余四类  
- 0 结果必须有价值  
- 关键跳转必须双证据链  
- 搜索不是透视，而是下潜  
- 七枚碎片通过异常关键词主动触发  
- 玩家搜一个词之后，必须更知道下一步该搜什么

本稿之后，任何 Batch 2–4 的记录设计若无法接入这套搜索语法，应修改记录，不修改语法。
