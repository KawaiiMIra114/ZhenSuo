# 《镇锁》Tech Vertical Slice & Trigger Engine PoC v1
## 技术切片与触发引擎验证文档 v1

> **文档职责**
> 本文档是给研发团队的“第一份试卷”。
> 目标是在不涉及复杂 UI 和长篇文案的前提下，用最简陋的 HTML/文本 跑通《镇锁》的底层核心机制：**统一搜索框 + 关键词触发网络**。
> 本测试通过后，方可启动全量内容（Phase 1-4）的配置。

### 一、 测试范围（Scope）

本次技术切片仅包含以下核心组件：
1. **一个全局唯一的搜索输入框**。
2. **两张极其简陋的测试页面**（只包含文字和基础排版）。
3. **一套底层的触发路由逻辑**（不使用 Elasticsearch 或全文检索，只做精准/正则映射）。
4. **三种防爆破/查询不足的系统反馈**。

---

### 二、 核心机制开发要求（Must-Haves）

#### 2.1 抛弃全库检索逻辑
前端输入框的内容提交后，**禁止**直接去数据库里 `LIKE '%keyword%'`。
必须走一层“路由分发”（Trigger Router）：
- 只有命中了系统预设的 `Trigger Term`，才返回对应的 `Record ID`。

#### 2.2 两段式页面渲染
页面渲染必须依赖传入的 `Record ID`：
- **页面 A（入口桩）**：包含一个初始信息。
- **页面 B（触发页）**：搜索特定词汇后返回的新页面。

---

### 四、 验收测试用例（Acceptance Criteria）

开发完成后，必须由测试/策划自行输入以下内容，验证结果是否**完全符合**预期。任何偏离均视为底层安全或体验漏洞。

| 测试动作 (输入词) | 预期系统行为 / 返回页面 | 验证目的 |
| :--- | :--- | :--- |
| **输入 `LX-044-YIN`** | 成功渲染页面 `CL-ARCH-RSP-LX-01`。 | 验证主线核心的“关键词精确触发新页面”逻辑是否成立。 |
| **输入 `林晓`** | **禁止**返回异常页。必须返回“查询不足”或“受限投影”文案（例：“当前检索范围过宽，或对象未公开索引”）。 | 验证系统是否做到了“基于查询精度门拦截”，防止玩家用常识词爆破内部逻辑。 |
| **输入 `OA` 或 `内部系统`** | **禁止**返回任何真实内部数据。必须返回目录投影（例：“仅返回公开设施目录，请补充具体模块名”）。 | 验证防未授权对象枚举机制。验证内部模块不能被“裸词”直达。 |
| **输入 `PHX-ALPHA`** | 返回受限投影（例：“查无公开释义，涉内部标签”）。 | 验证当玩家搜到了更深的词，但暂无对应具体深层记录时，系统不会泄露“权限不足”，而是反馈查询本身的问题。 |
| **输入 `随便打的乱码`** | 返回 0 结果标准文案（例：“当前索引范围内未形成稳定命中”）。 | 验证基础防错。 |
