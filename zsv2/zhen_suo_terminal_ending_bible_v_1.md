# 一、终局层到底负责什么

终局层不是最终资料库，也不是奖励动画前的问答环节。  
它在《镇锁》里的职责，是完成以下六件事：

## 1.1 把“真相已知”翻成“方案可执行”
OA 层已经完成了：
- DNR 真义翻转  
- B2 真义成立  
- 七节点结构可见  
- JiuKu / TaiYi 前影开始组装  
- 执行接口存在感成立

终局层必须再推进一步：
**让玩家从“理解系统”过渡到“选择如何对系统动手”。**

## 1.2 把七碎片从收集物翻成条件结构
在前几层里，碎片可以作为：
- 异常命中页  
- 赵启留下的拆机块  
- 结构化线索

终局层必须明确：
- 七碎片不是装饰奖励  
- 它们共同构成结局 C 的必要条件  
- 缺一，系统就不会真正被熄灭

## 1.3 把 TaiYi / JiuKu 从可组装对象翻成最终执行语义
前层只能做到：
- 让二者出现  
- 让二者同属一条线  
- 让玩家知道它们不是诗意暗号

终局层必须明确：
**`TaiYiJiuKu` 不是 lore，而是执行对象。**

## 1.4 把 A / B / C 从“选项”翻成“伦理后果”
终局层绝不能做成：
- 结局菜单  
- 单纯多结局图鉴  
- 三个按钮选喜欢的剧情

终局层必须让玩家感到：
- A 是用焚毁终止焚毁  
- B 是用自我替换换回林晓，但系统继续  
- C 是接力完成赵启没跑完的那一步，最好，但不圆满

## 1.5 把“最后一步”做成低语法高压力
终局层必须延续全作的统一语法：
- 阅读  
- 搜索  
- 对照  
- 输入 / 执行

不能突然引入：
- 复杂小游戏  
- 时限操作  
- 解锁拼图  
- 反射类交互

## 1.6 把结束做成余波，而不是奖励
本作终局不是为了制造“通关爽感”。  
终局层必须把玩家带到：
- 知道自己做了什么  
- 知道自己为什么这么做  
- 知道还有什么没被彻底解决

# 二、终局层的体验定位

## 2.1 体验定位一句话
终局层是《镇锁》的**执行与代价层**。

前面几层解决的问题是：
- 这是什么  
- 谁干的  
- 怎么运作  
- 谁留了路

终局层解决的问题是：
- 你到底要怎么动手  
- 你准备接受哪一种代价

## 2.2 终局层的核心问题
这一层只能围绕一个问题组织：

**你准备承担哪一种代价？**

不是“还有没有更多 lore”。  
不是“Meridian 后面还有什么组织”。  
不是“钟长明完整思想史是什么”。  
这些都不该在终局层扩散。

## 2.3 玩家感受目标
玩家应从：
- 我知道系统是什么
过渡到：
- 我知道可以怎么处理它
再过渡到：
- 我知道无论选哪条路，都会伤到某些东西

也就是说，终局层的重点不是信息量，而是**压力收束**。

# 三、总语法与交互规则

终局层依然服从**统一搜索框**。  
不新增“终局专属第三输入框”或“小游戏式控制台”。

## 3.1 允许的动作
- 搜索执行对象  
- 阅读执行说明 / 执行前对照  
- 查看七碎片状态  
- 输入最终执行对象  
- 阅读执行后返回页  
- 查看 A/B/C 三条路径对应的后果页

## 3.2 不允许的动作
- 时限输入  
- 手速判定  
- 拼图式“凑句子”小游戏  
- 多输入框混乱拼接  
- 纯菜单式选结局

## 3.3 终局层的信息密度原则
终局层不能再做大量横向扩张。  
它只允许三种信息：
- 执行条件  
- 执行逻辑  
- 执行后果

## 3.4 终局层记录产物规则
终局层部分页面可以只产出 1 个极强对象，不必强行塞到 3 个。  
因为这一层不是继续扩词，而是开始收束词。

推荐配比：
- 1 个主执行对象  
- 0–1 个支撑对象  
- 0–1 个余波对象

## 3.5 终局层的搜索语义
终局层搜索的目的，不再主要是“发现新世界”，而是：
- 确认条件是否满足  
- 组装执行对象  
- 触发执行接口  
- 理解不同方案的代价

# 四、终局层记录类型

终局层只使用以下八类记录：

## 4.1 TM-HUB｜终局索引记录
作用：告诉玩家，自己已经抵达执行层，并提供最后的有限结构。

## 4.2 TM-COND｜条件核对记录
作用：显示七碎片状态、执行前提、缺失条件，但不做游戏化进度条。

## 4.3 TM-EXEC｜执行说明记录
作用：解释某个执行对象的意义、边界与风险。

## 4.4 TM-INPUT｜执行接口记录
作用：真正接收最终输入，触发终局分歧。

## 4.5 TM-A｜A 方案记录
作用：焚毁路径的执行前说明与执行后结果。

## 4.6 TM-B｜B 方案记录
作用：替换路径的执行前说明与执行后结果。

## 4.7 TM-C｜C 方案记录
作用：七节点熄灭路径的执行前说明与执行后结果。

## 4.8 TM-AFTER｜余波记录
作用：结局后不是奖励页，而是余波页，负责把“结束”重新投回世界。

# 五、终局层的视觉与 UI/UX 总规范

## 5.1 视觉定位
终局层不应该突然“电影化”。  
它应保持：
- 冷静  
- 克制  
- 像系统最后一层，而不是演出舞台

## 5.2 不能长成什么样
- 不能像三按钮结局菜单  
- 不能像最终 Boss UI  
- 不能像剧情选择器  
- 不能像手游结局图鉴

## 5.3 页面头部规范
终局层所有记录都必须清楚显示：
- 记录号  
- 记录标题  
- 来源路径  
- 状态 / 条件（按需）

## 5.4 条件页规范
条件页必须给玩家“哪些东西已具备，哪些还不够”的判断依据。  
但绝不能写成：
- 7/7 收集进度条  
- 还差 1 个碎片的游戏 UI

正确做法应是：
- 执行结构完整 / 不完整  
- 节点响应可用 / 缺失  
- 某条件未满足时的系统化措辞

## 5.5 输入页规范（强制执行模式隔离）
输入页进入后，搜索框底层逻辑强制熔断，切换为"执行提交"模式。
- 不再属于普通搜索语义
- 输入TaiYiJiuKu但碎片条件不齐时，必须返回工程语义："结构未闭合 / 节点响应不足"
- 禁止返回"权限未解锁"或类似游戏化反馈

## 5.6 结局页规范
结局页的重点不是“告诉玩家赢了”，而是：
- 让玩家知道刚才执行的是什么  
- 让玩家理解结果为何如此  
- 让余波仍然压在世界上

# 六、终局层核心对象冻结

这一层最重要的对象只有六个：

## 6.1 `TaiYiJiuKu`
终局执行层最重要的主执行对象。  
它不是谜底，而是完成 C 方案的接口语义。

## 6.2 七碎片完整性
这是结局 C 的核心条件对象。  
必须通过“结构完整”表达，不通过进度条表达。

## 6.3 烈火
这是 A 方案的主执行语义。  
它必须像暴烈终止机制，不是简单自毁按钮。

## 6.4 替换 / 上行
这是 B 方案的主执行语义。  
它必须像一种可怕但看似温柔的系统接纳。

## 6.5 节点熄灭 / 释放
这是 C 方案的主后果语义。  
它必须表现为“算力来源被断掉”，不是“恶魔被打败”。

## 6.6 余波
这是所有结局的共同后部对象。  
本作不允许以一张“恭喜通关”结束。

# 十二、冻结结论

终局层正式冻结为：
- 《镇锁》的执行与代价层  
- 负责把真相转成方案，把碎片转成条件，把 TaiYi / JiuKu 转成执行对象，把 A/B/C 转成伦理后果

*本稿是《镇锁》终局执行层的完整执行文档。*  
*它规定的不只是终点长什么样，而是终点必须怎样把整部游戏压回一句话：你知道真相以后，准备怎么承担它。*
