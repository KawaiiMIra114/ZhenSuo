# 《镇锁》Unified Correction & Integration Patch v1
## 统一修订与整合补丁 v1

---

# 文档职责

本文档是《镇锁》所有下位执行文档的"解释器"与"总防线"。

由于早期的架构设计将搜索系统视为了"通用检索引擎"，导致在旧版的各层 Bible 中遗留了"越权枚举"、"备份直达"等不符合游戏机制的漏洞设计。

本补丁不推翻原有文档的世界观与体验核心，但强制规定在实际开发和文案落地时，如何动态替换旧文档中的错误设计口径。

---

# 一、解释优先级（强制执行）

当文档之间出现设定与设计冲突时，开发与文案团队必须严格按照以下顺序进行解释与执行：

1. **Retrieval, Trigger & Boundary Bible v1 (RTB Bible)**：最高法典，定义搜索与触发的物理法则。
2. **Unified Correction & Integration Patch v1**：本文档。
3. **各层原始 Bible 及 IA/Page Bible**：在不违背前两者的前提下，文案、UI、结构设计继续有效。

---

# 二、全局词汇与概念替换表

在阅读和执行任何原版 Bible 时，凡遇到左侧概念，必须在实现层替换为右侧概念：

| 原始（高危）口径 | 强制替换为的新口径 | 替换原因与影响 |
|---|---|---|
| 统一搜索系统 / 全局检索引擎 | 统一搜索框 + 关键词触发网络 | 搜索本质不是查数据库，而是用玩家输入的特定词"触发"预设的记录。 |
| Searchable Terms (通用搜索词) | 拆分为：Trigger / Echo / Output Terms | 必须精确区分：能拉出页面的词 (Trigger)、仅作回响的词 (Echo)、用来导向下一步的词 (Output)。 |
| 权限结果 / 系统识别但无权访问 | 查询不足结果 / 受限投影记录 | 彻底切断把权限提示做成"目标枚举器"的漏洞。不告诉玩家"你没权限"，只反馈"查询不够具体"或只给摘要。 |
| 原始备份库 / 处理前快照恢复 | 赵启整理的证据包 / 差异节选 | 影子档案不能是裸数据备份，必须是带缺损、被刻意整理以证明"有人动过手脚"的片段。 |
| 终局层的普通搜索动作 | 执行触发模式 (Execution Trigger) | 终局必须做到查询与执行隔离。在终局页面，输入动作不再是搜索资料，而是提交不可逆的执行方案。 |

# 三、逐本圣经修订指令

## 3.1 Forum Bible & IA (Batch 2) 修订

**原始错位**：部分设定可能暗示了"模糊搜索"能拉出相关簇的引擎感。

**落地要求**：
- **弱化发散**：论坛的搜索结果也是靠 Trigger Terms 严格映射出来的。
- **福生无量天尊 词性降级**：它首先必须作为 Echo Term (回响词) 存在于普通用户的吐槽帖中；只有在玩家结合更深的关联后，自行提取（或系统极弱暗示）的短语 `fswltz` 才转变为用于深层桥接的 Trigger Term。

## 3.2 Admin & Shadow Archive Bible 修订

**原始错位**：原文档将 OA 和管理员边界写成了"可被裸词直达"的页面，且影子档案等同于系统快照恢复。

**落地要求**：
- **禁止裸搜直达原件**：单搜 `bbs_admin` 或 `OA` 只能拉出"引用边界"或"公开层投影"，绝不能直接打开深层管理页。
- **启用查询精度门**：深层记录（如处理单、日志）必须由"组合词"（对象+语境，如 `8023 维护日志`）才能触发。
- **影子档案降级**：SA-ARCH-GH-01 等快照页面的文案，必须体现"这是有人匆忙截取留下的证据残片"，坚决不能做成完整的全页对比图。

## 3.3 OA Bible 修订

**原始错位**：将内部系统地图完全暴露，存在让玩家未鉴权就任意浏览敏感数据的风险。

**落地要求**：
- **最小必要泄露**：对于 OA-HR-01 (人事流转) 中的离岗时间和状态，默认模糊处理到"日"或更宽的时间窗。仅当需要与外部新闻（安宁路车祸）进行强逻辑对照时，才允许暴露能重识别的精确信息。打码是常态。
- 废除所有将 OA 系统写成"由于你权限不足，所以只能看到这些"的自我加戏话术，改为系统正常的局部投影展现。

## 3.4 Terminal & Ending Bible 修订

**原始错位**：统一个输入框既负责试错又负责终局执行，易导致误触与重放漏洞。

**落地要求**：
- **两段式分离**：进入 TM-INPUT-01 (执行接口) 页面后，搜索框底层逻辑强制熔断，切换为"执行提交"模式。
- 当玩家输入 `TaiYiJiuKu` 试图触发结局 C 时，若碎片条件 (TM-COND-01) 不齐，系统绝对禁止返回"权限未解锁"，必须严格返回属于机器工程语境的：**"结构未闭合 / 节点响应不足"**。

## 3.5 Content Production Master Sheet 修订

**原始错位**：排期表中的 Searchable Terms 与 Gate Type 字段定义陈旧。

**落地要求**：
- 文案排期表中的 `Searchable Terms` 列作废，必须扩充拆解为三列：`Trigger Terms`、`Echo Terms`、`Output Terms`。
- `Gate Type` 的判定标准不再是"身份权限有无"，而是"查询精度是否匹配"。
- 必须在总表中新增 `Projection Level` (投影层级) 一列，强制研发明确该页是属于"公开"、"证据"还是"执行"投影。

# 四、内容制作 QA 自检 5 问

在文案开始撰写或研发开始配置任何一页之前，必须用这 5 个问题过一遍：

1. 这页是被什么具体的词汇 **触发** 出来的？（不要回答"搜出来的"）
2. 玩家搜的如果是个宽泛的裸词，这页是不是不小心把底牌全交了？
3. 如果这是个深层证据（如影子档案），它看起来像不像被赵启刻意"整理"和"剪辑"过？
4. 这页读完，有没有给玩家至少一个明确的 Output Term 拿去进行下一步？
5. 如果玩家触发条件不足，返回的文案是不是合理的"查询不足/不包含该信息"，而不是在炫耀"这里有秘密但你进不来"？
